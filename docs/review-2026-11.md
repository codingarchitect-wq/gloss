# Code review, November 2026: what's left

A full review of Gloss on 2026-11-02. The three high-severity findings are fixed on the
`local-docker` branch (see the end). Everything below is still open, worst first.
Line numbers are as of that branch.

Findings marked **verified** were confirmed by reading the code path end to end (or, where
noted, by running it); the rest come from the same review but have not been reproduced yet.

## Medium

### 1. MCP batches get around the rate limit and the daily save cap
`lib/mcp.ts:135-138`, `savesLeft` at `:246`. **Verified (code).**
The 60-a-minute limit is counted once per HTTP request, but a request may be a JSON-RPC
batch of any length, and every message runs at once (`Promise.all`). Each `save_articles`
call works out its own daily allowance from a snapshot of the shelf, so N calls in one batch
each get the full 1,000, and each starts 4 page fetches in parallel.
*Scenario:* one POST with 200 `tools/call save_articles` messages of 25 URLs each starts
800 concurrent outbound fetches and up to 5,000 saves, all inside a single "request".
*Fix:* cap the batch length (a few messages), count each `tools/call` against the limiter,
and run batched calls one after another so the shelf snapshot stays current.

### 2. "Read it more carefully" page cap is weak
`app/api/pdf-careful/route.ts:19, 36-77`. **Verified (code).**
The 200-pages-a-day cap is kept per hash of the reader's key, with no overall ceiling, so
anyone with several valid keys multiplies it on the operator's LlamaParse account
($0.0125 a page). Without `DATABASE_URL`, `pagesToday` returns 0 and `record` does nothing,
so there is no cap at all. The check comes before the parse and the record after it, so
parallel requests all pass. `truncated` is also wrong when the daily remainder, not
`MAX_PAGES`, cut the read short.
*Fix:* a global daily page budget, an in-memory fallback without a database (as
`lib/quota.ts` has), and reserve pages before parsing.

### 3. Follow-up questions never send the model its own first answer
`lib/ask.ts:47`. **Verified (code).**
`turns[0]` is the first answer, but history is built from `turns.slice(1, -1)`, so for
`[A0, U1, A1]` the model gets only the question U1. "Say that more simply" has nothing to
refer to. Dropping errored assistant turns can also leave two user turns back to back.
*Fix:* `slice(0, -1)`, and drop an errored assistant turn together with the user turn before it.

### 4. One rejected push stops all syncing, silently and for good
`lib/sync.ts:35, 122-160`.
Batch and row sizes are counted in UTF-16 characters (`JSON.stringify(...).length`), but the
server and Vercel limit bytes, so a 1.5M-character batch of CJK text is ~4.5 MB and gets a 413.
There is also no row cap on the client, while the server refuses more than 2,000 rows (a
signed-out reader with thousands of highlights signing in). `flush` throws, `serial` swallows
it, and the next push rebuilds the same batches in the same order: everything after the bad
batch never syncs, and the reader is never told.
*Fix:* measure with `new TextEncoder().encode(...).length`, cap rows per batch below 2,000,
and on a 413 split the batch (or skip and report the one bad row) instead of retrying it whole.

### 5. Switching accounts on one browser mixes libraries and can delete texts
`lib/sync.ts:91-96, 124-127`.
The baseline is kept per user, but the local store is shared. When user B signs in on A's
browser, all of A's library is uploaded into B's account (a privacy problem). If B then
removes those books and A signs back in, A's old baseline turns them into tombstones and A's
texts are deleted from A's account and devices.
*Fix:* partition the local store per user (or clear it on sign-out, after offering an export),
and never upload a library that was built under another account without asking.

### 6. Two open tabs overwrite each other's saved state
`lib/store.ts:375-395` (write at `:391`).
Every tab writes its whole in-memory snapshot to `gloss:v1`, and nothing listens for
`storage` events, so the last tab to write wins. A highlight made in tab 1 is lost when tab 2,
open on another text, saves its reading progress a moment later.
*Fix:* listen for `storage` events (or a `BroadcastChannel`) and merge, or write per entity.

### 7. localStorage failures are silent, and sync doubles what is stored
`lib/store.ts:390-392`, `lib/sync.ts:97-101`.
Writes catch and ignore quota errors. The sync baseline stores each entity's full JSON
(whole gloss answers included), roughly doubling localStorage use for signed-in readers.
At around 1,000 glosses the ~5 MB origin quota is reached, and from then on nothing is saved
and nothing is said. *Fix:* store a hash in the baseline, and tell the reader when a save fails.

### 8. Saves can be starved, and nothing is saved on close
`lib/store.ts:387-393`.
Every store change restarts the 400 ms save timer, with no maximum wait. A streaming answer
changes the store every frame, so nothing is written for the whole answer, and there is no
`pagehide` flush. A highlight made during a long answer is lost if the tab closes first.
*Fix:* a max-wait on the debounce and a flush on `pagehide`/`visibilitychange`.

### 9. IndexedDB helpers can report success for failed writes, or hang
`lib/store.ts:406-426`.
The transaction helper resolves on the request's `onsuccess`, not the transaction's
`oncomplete`, so a quota abort at commit still reports success and the "storage is full"
paths (`lib/import.ts:63`, `lib/careful.ts:50`) never fire. There is no `onblocked` or
`onversionchange` handler, so a future version bump hangs every load and save while an old
tab is open. *Fix:* resolve on `oncomplete`, reject on `onabort`, close on `onversionchange`.

### 10. Any shelf change re-uploads the article's full text, and can roll back a newer one
`lib/sync.ts:116-121` (load at `:119`).
The comment says the text goes up with the first shelf entry and when its `rev` changes, but
the code attaches it on every shelf-field change (favorite, topic, title). The server keeps
whatever text comes last, so a device holding an older text can overwrite a newer careful
read, and highlights made on the new text then point at the wrong passages. The first push
after sign-in also loads every text into memory at once.
*Fix:* send the text only when the shelf entry is new to the server or its `rev` changed.

### 11. "Read it more carefully" leaves the old upgrade queue, which appends duplicate pages
`lib/careful.ts:49`, `lib/upgrade.ts:139-148`.
The careful text keeps `article.upgrade`. Its blocks have no `page`, so each queued page
looks plausible and its vision reading is appended at the end, up to 30 duplicate pages,
which then sync. *Fix:* drop `upgrade` from the careful text.

### 12. Temporary failures quietly drop PDF pages
`lib/upgrade.ts:117-131`, `lib/pdf.ts:279-297`.
A 429, a 502 or a network error while upgrading a page takes the "not better" branch, so the
page leaves the queue for good. At import, a scanned page whose vision read fails for any
reason other than `need_key` falls back to an empty text layer and is not queued, so a
scanned PDF can import with pages missing and no sign of it.
*Fix:* keep failed pages queued (with a retry limit), and mark pages that could not be read.

## Low

- **A selection ending at the very start of the next block highlights that whole block**
  (`lib/anchor.ts:28-66`). Triple-click usually ends a selection there in Chromium and Safari.
  Needs a check in a browser.
- **`/api/brief` has no size limit** on the document (`/api/ask` caps it at 600k characters),
  with thinking on and 16k output tokens. One free request can cost more than the allowance.
- **Pages are downloaded in full before their size is checked** (`lib/fetch-article.ts:182, 192`).
  Read the stream and stop at the limit. Five redirect hops at 15 s each can also outlast the
  route's 30 s `maxDuration`.
- **The client IP is taken from `X-Forwarded-For` as sent** (`lib/ratelimit.ts:8`). Fine on
  Vercel, which overwrites it; behind another proxy anyone can fake it and get a fresh free
  allowance per request.
- **`/api/sync` checks the size of `data` but not of `doc`**, trusts `content-length` when a
  body is chunked, and has no storage cap per account (`app/api/sync/route.ts`).
- **Painted covers are cached as `immutable` for a year** (`app/api/covers/[id]/route.ts:12`),
  but a cover can be repainted under the same id.
- **Removing a book leaves its highlights, glosses, brief and progress behind** (`removeFromLibrary`
  in `lib/store.ts`). They keep syncing, and exports list them under the article id.
- **Read-aloud stops when a background PDF page upgrade lands** (`components/reader/Listen.tsx:261`).
- **The landing page's drop handler ignores `busy`** (`components/landing/Landing.tsx`), so two
  imports can run at once.
- **No `online` listener**: changes made offline wait for the next edit before they sync.
- **Agent tokens can sit in URLs** (`app/mcp/[token]/route.ts`), where they end up in logs.
  Already noted in the code, waiting on OAuth.

## Fixed on the `local-docker` branch

- **Private-address filter bypass (SSRF).** `http://[::ffff:127.0.0.1]/` and other IPv6
  spellings of private addresses got through, and DNS was checked at a different moment from
  the connection. Now `lib/public-net.ts` allows only public unicast, and checks again at
  connect time for every socket, by name or by IP.
- **Next.js 16.4.0 had critical advisories.** Upgraded to 16.4.4; `npm audit` is clean.
- **A pull overwrote changes not yet pushed** (`lib/sync.ts`, `pull`). Edits came undone and
  removed books came back. A change made here and not yet pushed now wins until it is pushed.
